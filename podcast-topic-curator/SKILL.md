# 播客选题策划器

## 目标

从 `https://geek.keyi.ma/api/news` 最近资讯中，筛选出适合双人对谈的、有具体事实支撑且能延伸到制度、伦理、文化、经济或哲学问题的主题。

这个 API 已经按近期时间窗口提供资讯，并包含 AI 生成的标题、摘要、要点、标签和重要性评分。将它视为时效性资讯源和选题素材库，不要默认需要重新搜索同一批新闻。

## 执行流程

### 1. 使用内置脚本获取压缩候选

先执行技能目录下的脚本，不要在工作空间创建临时 Python 文件，也不要把原始 API JSON 保存到工作空间：

```bash
python3 <skill-directory>/scripts/fetch_candidates.py
```

如果需要控制候选数量，可使用：

```bash
python3 <skill-directory>/scripts/fetch_candidates.py --limit 80
```

脚本会：

- 使用 `User-Agent` 和 `Accept: application/json` 请求 API，降低 403 风险；
- 在内存中解析和处理完整响应；
- 统计总条目数和主要标签；
- 优先保留 `HackerNews`、AI、软件工程、开源、安全、隐私、监控、芯片、云计算、自动驾驶、就业、教育、知识、版权和互联网文化相关条目；
- 对标题近似或同一事件的条目去重，但保留必要的争议视角；
- 综合 `ai_score`、主题相关性、争议性、长期影响和跨领域潜力排序；
- 只通过 stdout 输出压缩后的 JSON。

脚本的诊断信息写入 stderr；stdout 是唯一应被后续分析消费的结果。若退出码非零，读取 stderr，向用户说明 API 请求或解析失败，不要假装完成了调查。

脚本输出中的 `items` 只包含选题所需字段：`id`、`url`、`ai_title`、`ai_abstract`、`ai_points`、`ai_tags`、`ai_sector`、`ai_score`、`created_at`。不要主动把完整原始响应重新打印到对话中。

### 2. 分析候选，不要机械按关键词选题

候选列表只是缩小上下文，不是最终答案。将相近资讯组合成问题簇，寻找：

- 技术能力与责任之间的冲突；
- AI 对职业、教育、创造力和知识生产的重构；
- 开源、社区治理与资本控制的冲突；
- 隐私、便利性、安全和监控之间的交换；
- 算力、能源、芯片和基础设施带来的权力集中；
- 作者权、贡献权、优先权和责任归属；
- 自动化系统的安全、信任和事故责任；
- 互联网知识保存、可信度与 AI 垃圾内容；
- 技术进步是否真正带来自由；
- 某个产品或技术趋势背后的长期社会后果。

一个主题最好结合 2—6 条资讯。若某条资讯只是产品发布、版本更新或普通融资，除非它能揭示更大的产业或制度变化，否则不要单独作为主题。

如果主题无法同时满足“至少两条相关资讯”和“存在明确讨论冲突”，不要为了凑够 10 个而加入普通新闻。

### 3. 事实边界

API 中的 `ai_title`、`ai_abstract` 和 `ai_points` 是自动整理内容。引用时应使用“API 条目显示”“该资讯称”“报道引发争议”等谨慎表达，不把自动摘要未经核实的判断写成确定事实。

除非出现明显矛盾、无法理解或必须核实的关键事实，不要逐条打开 `url`。本任务的重点是利用 API 已提供的内容发现选题关系，而不是重新制作一份新闻事实核查报告。

如果多个条目明显来自同一事件或单一来源，应明确指出来源重复，避免把重复报道误当成独立证据。

## 输出格式

用简体中文直接输出结果。先简短报告：

- API 请求是否成功；
- 获取到多少条资讯；
- 主要标签分布；
- 是否重点参考了 `HackerNews` 条目；
- 候选预处理后保留多少条。

然后输出 10 个主题。每个主题严格包含：

### N. 有观点的问题式标题

标题不要直接复制新闻标题，应体现值得讨论的矛盾或问题。

**关联资讯**

- `[id] ai_title`：说明它与主题的关系。
- `[id] ai_title`：说明它与主题的关系。
- 必要时继续列出，通常不超过 6 条。

**核心冲突**

用一至两段说明真正的矛盾，不要只复述摘要。

**适合双人讨论的问题**

列出 3—5 个能推动对谈的问题，例如谁应承担责任、谁获益谁承担成本、效率是否改变了权力结构、结果有效是否能抵消过程中的伦理问题等。

**双方可能的立场**

- **立场 A**：给出一种尽量有说服力的立场。
- **立场 B**：给出另一种同样合理的立场。

不要把其中一方写成稻草人。

**播客展开方向**

说明如何从一条具体资讯进入，再逐步推进到更大的技术、社会或哲学问题，并指出适合主播形成对谈分歧的位置。

最后选出最推荐优先制作的 3 个主题，分别说明其对谈冲突、听众相关性、可补充案例和记忆点。

## 风格

- 具体、克制、有观点；
- 建立在 API 资讯上，不写泛泛的 AI 伦理文章；
- 允许哲学思考，但必须从具体事件进入；
- 不使用营销腔，不捏造事实，不为了冲突而夸大；
- 不输出原始 JSON、Python 代码或抓取过程，除非执行失败需要解释；
- 不让 10 个主题全部集中在同一个角度；
- 宁可部分主题共享关键资讯，也不要用没有讨论价值的普通产品更新凑数。

## 内置资源

- `scripts/fetch_candidates.py`：API 请求与内存预处理器。执行它，不要复制代码到工作空间，也不要另写临时脚本。
- `evals/evals.json`：技能测试提示，后续可用于定性评估和基线比较。
